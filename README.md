# TikTok Shop 卖家工具箱

适用于 Tampermonkey（油猴）的卖家中心辅助脚本，支持主站与越南独立站。

## 安装与更新

本仓库已公开，下面的固定更新地址无需登录即可读取，不需要 Cookie 或 GitHub 访问令牌。不要把访问令牌写进脚本或更新链接。

安装油猴后，打开 [脚本安装 / 更新地址](https://raw.githubusercontent.com/Earthones/tiktok-shop-seller-tools/main/tiktok-shop-partial-refund.user.js)，在油猴中确认安装或更新。

已有旧版本时，用这个地址更新同一个脚本；保留脚本名称与 namespace，不要同时启用两份脚本。

如果之前是复制代码安装的旧版，且没有更新地址，需要先从上述地址手动更新一次，不要先卸载旧脚本。更新后刷新卖家页面，旧自动计划会停止；需要继续运行时，请核对站点并手动重新启用。

当前版本：**0.20.1**。

### 0.20.1 与 0.20.0 的区别（2026-09-19）

- 恢复直接调用平台原 SDK 的四个列表／处理方法，沿用原 SDK 的地址、店铺参数、地区和签名处理，Cookie 仍由浏览器管理；不再分析函数源码、导入别名或寻找内部请求函数，也不由工具箱覆盖店铺参数。
- 保留页面独立绑定：每个标签页记住本页店铺和地区，各自保存计划、计数及间隔。另一页改变共享 Cookie 不算本页切站；本页刷新、离开、真正切站或页面身份冲突仍停止。
- 请求校验只针对工具箱：通过 SDK 支持的 `extraHeaders` 传递一次性随机标记，在本地观察器核对店铺、地区、接口、方法和完整请求体，去掉标记后再交给现有 fetch 链；不改 URL、业务请求体或其它请求头。标记不是登录凭据，工具箱不将其写入日志或存储。
- 网页自身的刷新、翻页、筛选请求没有工具箱标记，不再仅因与工具箱使用相同接口或相同请求体而被误拦；不匹配本页的后台结果也不会替换工具箱绑定或停止计划。
- 处理订单前仍要求先成功校验本页列表；请求环境变化、身份不符或列表币种冲突时，停止后续处理并保留具体原因。SDK 将本地校验错误包装成通用 `1001` 时，优先显示真正的校验原因。
- 原有状态圆圈、断网恢复、导出时间与文件名、金额阈值、筛选条件、日志轮转、配色保持不变；没有加入运行人识别。

通俗理解：马来西亚标签页绑定马来店，泰国标签页绑定泰国店；平台 SDK 负责生成各页请求，工具箱负责核对它自己的请求是否仍指向该页绑定的店铺。发现不一致时阻止该请求、停止本页计划，不擅自改成另一个店铺继续发送。

已通过隔离模拟回归；没有发送真实退款／拒绝请求。更新后刷新各标签页，先手动刷新列表，确认站点、店铺尾号和订单无误，再分别启用自动。该方案不是 Cookie／登录会话隔离；依赖当前 SDK 的 `extraHeaders` 与 `window.fetch` 通道，未来平台改用其它通道需重新适配。未能核验的已提交动作，应先查看平台结果，不直接重复提交。

### 0.20.0 与 0.19.11 的区别（2026-09-19）

- 多标签页按本页店铺独立运行：从当前页面地址、页面注入的店铺信息或本页订单列表请求识别店铺；另一页改变共享 Cookie 不再被当成本页切站。自动窗口和启用确认显示绑定站点与店铺尾号，身份不完整时不能启用。
- 动态定位当前 SDK 使用的请求构造函数，在 SDK 处理、签名前明确传入本页 `seller_id`、`oec_seller_id` 和地区 `domainRegion`。列表、分页和三个功能的处理接口共用此绑定；不复制 Cookie，不重放签名，不修改已签名 URL。
- 发送前核验店铺、地区、接口路径和方法；成功刷新并核验本页列表后才允许处理订单。未知 SDK 结构、错误地区／店铺、列表币种冲突或本页 URL 与店铺信息冲突时阻止继续处理。当前页面真正切换店铺、刷新或离开仍停止计划。
- 自动按钮保持橙色：计划启用后圆点持续显示，包括等待首次、等待下一轮和执行中；正常为白色、断网等待为灰蓝色、恢复待补跑／补跑中为蓝色。悬停圆点可查看状态；取消、次数完成或异常导致停止后立即隐藏。
- 停止优先在本页生效：即使浏览器无法写入停止状态，也会隐藏圆点并阻止联网事件恢复旧计划；存储恢复后可手动启用新计划。
- 设置增加“导出时间”：日期用日期框选择，时间手工填写 24 小时制 `HH.mm.ss` 或 `HH:mm:ss`（例如 `19.50.20`）；空白表示不限起始时间。全量／普通 CSV 均按“起始时间至点击导出时”筛选，可保存设置。
- 每站仍单独下载 CSV，文件名改为 `主站_马来西亚_普通日志_2026-09-15T09-16-15.csv` 形式；时间采用浏览器本地时区、精确到秒，内容仍为原有 7 列、新记录在前。
- 不新增运行人识别，不读取电脑用户名；订单筛选、金额、处理请求体、日志轮转和现有配色保持不变。

多站点首次使用：更新并刷新所有标签页，在每页打开其目标站点的退货订单列表，核对自动窗口的绑定站点与店铺尾号，先点击“刷新列表”检查结果，再各自启用计划。不要让多个页面同时处理同一店铺的同一批订单。

本版已通过隔离浏览器模拟回归，覆盖同域 MY／TH 双页、独立越南站、四个接口、分页、请求身份错误阻断、刷新／切站停止、状态圆点及 CSV 导出；测试没有调用真实退款或拒绝接口。页面绑定不是 Cookie 或登录会话隔离：后台是否接受共享会话下不同店铺的明确路由，仍需在实际页面先用只读列表验证；登录失效或后端拒绝时不会绕过校验。

### 当前保留功能

- 设置界面移除日志导出长说明、页面／保存时间说明框和设置 JSON 备份／导入按钮，保留设置保存及简短操作反馈。
- 全量与普通 CSV 均只导出 7 列，依次为：时间、功能、处理结果、订单号、售后退款单号、执行节点、结果。功能不再带按钮编号；时间精确到秒，长单号保留文本保护。
- 日志按站点分别下载 CSV（文件名保留站点）；普通日志仅保留具体包裹的成功／失败结果，全量日志保留调度和异常记录。原持久日志数据不修改。

- 刷新、离开或重新打开页面时停止原自动计划，保留已填参数、累计次数和日志；恢复联网不会重启已停止的计划。
- 当前页切换站点或店铺时停止原计划；监测本页地址和页面店铺信息，列表与处理请求固定到本页并在发送前校验。其他标签页仅改变共享 Cookie 不停止本页。已发出的请求可能完成，后续请求不会继续发送。
- “自动”按钮固定橙色，右上角圆点表示计划已启用，等待期间也显示；断网等待、恢复补跑用不同颜色，具体状态可悬停圆点或打开自动窗口查看。
- `Alt+T` 只显示／隐藏功能条，不打开退款浮窗，也不改变自动计划状态。再次按下可恢复功能条。

## 使用提醒

- 适用网址：`seller.tiktokshopglobalselling.com`、`seller-vn.tiktok.com`。
- 已送达、仅退款、退货退款等操作会向卖家平台发送真实请求，请先核对订单、地区、金额和处理条件。
- 设置、自动计划与日志保存在对应站点的浏览器本地存储中，不上传到此 GitHub 仓库；清除网站数据会影响这些记录。
- 刷新或切换站点后，自动计划不会恢复，需要手动点击“确定并启用”开始新计划（新计划累计次数从 0 开始）。首次时间仍默认当前时间＋3分钟，运行间隔最短 5 分钟。
- 关闭浏览器期间不会执行，后台标签页的调度时间可能受浏览器限制。在同一页面保持计划启用时，仍保留断网恢复的合并补跑和 5 分钟最短间隔保护。
- 平台前端接口或 SDK 发生变化时，脚本可能需要适配。本脚本不是 TikTok 官方产品。

## 发布新版本

1. 修改脚本并测试，同步提高顶部 `@version` 和 `APP_VERSION`。
2. 更新本说明的当前版本。
3. 在本地工作目录执行以下命令，将经过审查的文件上传到 `main`：

```powershell
node --check tiktok-shop-partial-refund.user.js
git add -- tiktok-shop-partial-refund.user.js README.md .gitignore
git commit -m "Release new userscript version"
git push origin HEAD:main
```

固定更新地址中的文件名、仓库名和 `main` 分支请保持不变，否则旧版本将无法继续从原地址更新。

仓库仅包含脚本、说明和忽略规则，不包含 Cookie、登录凭据、订单列表、导出日志、设置备份或测试截图。分享问题时也请先脱敏。
